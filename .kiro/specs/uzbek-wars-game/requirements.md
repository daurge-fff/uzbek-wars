# Документ требований: Узбек Варс

## Введение

Узбек Варс - это веб-игра с узбекской народной эстетикой, где игроки выбирают и прокачивают персонажа-узбека, выполняя различные игровые активности. Игра поддерживает четыре языка интерфейса и предоставляет систему прогрессии персонажа через выполнение различных действий.

## Глоссарий

- **Система** (System): Веб-приложение "Узбек Варс"
- **Игрок** (Player): Пользователь, взаимодействующий с игрой
- **Персонаж** (Character): Игровой аватар узбека, выбранный и прокачиваемый игроком
- **Активность** (Activity): Игровое действие, которое может выполнить персонаж (работа, грабеж и т.д.)
- **Прогрессия** (Progression): Система развития персонажа через накопление опыта и улучшение характеристик
- **Локализация** (Localization): Перевод интерфейса на поддерживаемые языки
- **База_Данных** (Database): MongoDB база данных для хранения игровых данных
- **Контейнер** (Container): Docker контейнер для изоляции и развертывания приложения
- **Донат** (Donation): Система добровольных платежей от игроков
- **Сом** (Som): Узбекская национальная валюта, используемая как игровая валюта
- **PWA** (Progressive_Web_App): Прогрессивное веб-приложение, которое может работать как нативное приложение

## Требования

### Требование 1: Выбор персонажа

**Пользовательская история:** Как игрок, я хочу выбрать уникального персонажа-узбека, чтобы начать игру с персонализированным аватаром.

#### Критерии приемки

1. КОГДА игрок впервые запускает игру, ТО Система ДОЛЖНА отобразить экран выбора персонажа
2. Система ДОЛЖНА предоставить минимум 3 различных персонажа-узбека для выбора
3. КОГДА игрок выбирает персонажа, ТО Система ДОЛЖНА сохранить выбор в База_Данных MongoDB
4. КОГДА игрок возвращается в игру, ТО Система ДОЛЖНА загрузить ранее выбранного персонажа из База_Данных
5. Система ДОЛЖНА отображать визуальное представление каждого персонажа в узбекском народном стиле

### Требование 2: Система прогрессии персонажа

**Пользовательская история:** Как игрок, я хочу прокачивать своего персонажа, чтобы видеть прогресс и становиться сильнее.

#### Критерии приемки

1. Система ДОЛЖНА отслеживать уровень персонажа, начиная с уровня 1
2. Система ДОЛЖНА отслеживать опыт персонажа в числовом формате
3. КОГДА персонаж набирает достаточно опыта, ТО Система ДОЛЖНА повысить уровень персонажа на 1
4. КОГДА уровень персонажа повышается, ТО Система ДОЛЖНА отобразить уведомление о повышении уровня
5. Система ДОЛЖНА сохранять прогрессию персонажа в База_Данных MongoDB
6. Система ДОЛЖНА отображать текущий уровень и опыт персонажа в интерфейсе игры

### Требование 3: Игровые активности

**Пользовательская история:** Как игрок, я хочу выполнять различные активности, чтобы зарабатывать опыт и ресурсы.

#### Критерии приемки

1. Система ДОЛЖНА предоставить активность "Работать в Связном"
2. Система ДОЛЖНА предоставить активность "Грабить"
3. Система ДОЛЖНА предоставить минимум 3 различные игровые активности
4. КОГДА игрок выбирает активность, ТО Система ДОЛЖНА выполнить действие и обновить состояние персонажа
5. КОГДА активность завершается, ТО Система ДОЛЖНА начислить опыт персонажу
6. КОГДА активность завершается, ТО Система ДОЛЖНА отобразить результат действия игроку
7. Система ДОЛЖНА отображать доступные активности в интерфейсе игры

### Требование 4: Система ресурсов

**Пользовательская история:** Как игрок, я хочу зарабатывать и тратить узбекские сомы, чтобы взаимодействовать с игровой экономикой.

#### Критерии приемки

1. Система ДОЛЖНА отслеживать количество узбекских сомов персонажа
2. КОГДА персонаж выполняет активность, ТО Система ДОЛЖНА начислить или списать сомы в зависимости от типа активности
3. Система ДОЛЖНА отображать текущее количество сомов в интерфейсе игры с символом валюты
4. Система ДОЛЖНА сохранять количество сомов в База_Данных MongoDB
5. ЕСЛИ количество сомов недостаточно, ТО Система ДОЛЖНА предотвратить выполнение активностей, требующих оплаты

### Требование 5: Мультиязычность

**Пользовательская история:** Как игрок, я хочу играть на своем родном языке, чтобы лучше понимать игровой контент.

#### Критерии приемки

1. Система ДОЛЖНА поддерживать русский язык интерфейса
2. Система ДОЛЖНА поддерживать узбекский язык интерфейса
3. Система ДОЛЖНА поддерживать украинский язык интерфейса
4. Система ДОЛЖНА поддерживать английский язык интерфейса
5. КОГДА игрок выбирает язык, ТО Система ДОЛЖНА переключить весь интерфейс на выбранный язык
6. Система ДОЛЖНА сохранять выбранный язык в База_Данных MongoDB для аутентифицированных пользователей
7. КОГДА игрок возвращается в игру, ТО Система ДОЛЖНА загрузить ранее выбранный язык
8. Система ДОЛЖНА отображать переключатель языков в интерфейсе игры

### Требование 6: Узбекская культурная эстетика

**Пользовательская история:** Как игрок, я хочу видеть узбекскую народную эстетику, чтобы погрузиться в культурную атмосферу.

#### Критерии приемки

1. Система ДОЛЖНА использовать узбекские культурные элементы в визуальном дизайне
2. Система ДОЛЖНА включать изображения плова и других узбекских культурных символов
3. Система ДОЛЖНА использовать цветовую палитру, соответствующую узбекской народной эстетике
4. КОГДА отображаются персонажи, ТО Система ДОЛЖНА показывать их в узбекской народной одежде или стиле

### Требование 7: Хранение данных в MongoDB

**Пользовательская история:** Как разработчик, я хочу хранить все игровые данные в MongoDB, чтобы обеспечить надежное и масштабируемое хранение.

#### Критерии приемки

1. Система ДОЛЖНА подключаться к MongoDB Atlas по URI из переменных окружения
2. Система ДОЛЖНА хранить данные персонажей в коллекции MongoDB
3. КОГДА состояние игры изменяется, ТО Система ДОЛЖНА сохранить изменения в База_Данных
4. КОГДА игрок закрывает и открывает игру, ТО Система ДОЛЖНА восстановить все данные из База_Данных
5. Система ДОЛЖНА сохранять выбранного персонажа, уровень, опыт и валюту в База_Данных
6. ЕСЛИ подключение к База_Данных недоступно, ТО Система ДОЛЖНА отобразить сообщение об ошибке
7. Система ДОЛЖНА использовать индексы MongoDB для оптимизации запросов к данным игроков

### Требование 8: Конфигурация через переменные окружения

**Пользовательская история:** Как разработчик, я хочу управлять конфигурацией через .env файл, чтобы безопасно хранить чувствительные данные.

#### Критерии приемки

1. Система ДОЛЖНА читать URI подключения к MongoDB из переменной окружения MONGODB_URI
2. Система ДОЛЖНА читать имя базы данных из переменной окружения DB_NAME
3. Система ДОЛЖНА читать порт приложения из переменной окружения PORT
4. Система ДОЛЖНА читать настройки донатов из переменных окружения
5. ЕСЛИ требуемые переменные окружения отсутствуют, ТО Система ДОЛЖНА завершить работу с понятным сообщением об ошибке
6. Система ДОЛЖНА включать файл .env.example с примерами всех необходимых переменных
7. Файл .env ДОЛЖЕН быть добавлен в .gitignore для защиты чувствительных данных

### Требование 9: Контейнеризация и развертывание

**Пользовательская история:** Как разработчик, я хочу запускать приложение в Docker контейнере, чтобы обеспечить изолированное и воспроизводимое окружение.

#### Критерии приемки

1. Система ДОЛЖНА включать Dockerfile для сборки образа приложения
2. Система ДОЛЖНА включать docker-compose.yml для оркестрации контейнеров
3. Контейнер ДОЛЖЕН проксировать приложение на порт 3060 хоста
4. Система ДОЛЖНА включать скрипт rebuild.sh для пересборки контейнера
5. Скрипт rebuild.sh ДОЛЖЕН останавливать контейнеры, очищать кэши Docker и пересобирать образ
6. Скрипт rebuild.sh ДОЛЖЕН очищать кэши aaPanel если они присутствуют
7. КОГДА выполняется rebuild.sh, ТО Система ДОЛЖНА полностью пересоздать контейнер с чистого состояния
8. Система ДОЛЖНА включать .dockerignore для исключения ненужных файлов из образа

### Требование 10: Система донатов

**Пользовательская история:** Как игрок, я хочу поддержать разработчиков донатом, чтобы помочь развитию игры.

#### Критерии приемки

1. Система ДОЛЖНА отображать кнопку или раздел для донатов в интерфейсе
2. Система ДОЛЖНА поддерживать интеграцию с платежной системой для приема донатов
3. КОГДА игрок совершает донат, ТО Система ДОЛЖНА записать информацию о донате в База_Данных
4. Система ДОЛЖНА отображать благодарность игроку после успешного доната
5. ГДЕ донаты включены, Система ДОЛЖНА предоставить игроку бонусы или преимущества за донат
6. Система ДОЛЖНА хранить настройки платежной системы в переменных окружения
7. Система ДОЛЖНА логировать все транзакции донатов для аудита

### Требование 11: Веб-интерфейс

**Пользовательская история:** Как игрок, я хочу играть через веб-браузер, чтобы не устанавливать дополнительное программное обеспечение.

#### Критерии приемки

1. Система ДОЛЖНА работать в современных веб-браузерах (Chrome, Firefox, Safari, Edge)
2. Система ДОЛЖНА быть отзывчивой и работать на экранах различных размеров
3. КОГДА игрок взаимодействует с элементами интерфейса, ТО Система ДОЛЖНА предоставить визуальную обратную связь
4. Система ДОЛЖНА загружаться за время не более 5 секунд при стандартном интернет-соединении
5. КОГДА происходит ошибка, ТО Система ДОЛЖНА отобразить понятное сообщение об ошибке на выбранном языке

### Требование 12: Mobile-First дизайн

**Пользовательская история:** Как игрок на смартфоне, я хочу комфортно играть на мобильном устройстве, чтобы играть в любое время и в любом месте.

#### Критерии приемки

1. Система ДОЛЖНА быть разработана с приоритетом на мобильные устройства (mobile-first подход)
2. Система ДОЛЖНА корректно отображаться на iPhone всех современных моделей
3. Система ДОЛЖНА корректно отображаться на Android смартфонах различных размеров
4. Система ДОЛЖНА использовать адаптивный дизайн с точками останова для различных размеров экранов
5. КОГДА игрок использует сенсорный экран, ТО Система ДОЛЖНА обеспечить удобные области нажатия минимум 44x44 пикселя
6. Система ДОЛЖНА использовать viewport meta-тег для корректного масштабирования на мобильных устройствах
7. Система ДОЛЖНА предотвращать горизонтальную прокрутку на мобильных устройствах
8. Система ДОЛЖНА использовать анимации и переходы, оптимизированные для мобильных устройств

### Требование 13: PWA и подготовка к нативным приложениям

**Пользовательская история:** Как игрок, я хочу установить игру на домашний экран и использовать её как приложение, чтобы иметь быстрый доступ.

#### Критерии приемки

1. Система ДОЛЖНА быть реализована как Progressive Web App (PWA)
2. Система ДОЛЖНА включать manifest.json с метаданными приложения
3. Система ДОЛЖНА включать Service Worker для офлайн-функциональности
4. Система ДОЛЖНА предоставлять иконки приложения для iOS и Android в требуемых размерах
5. КОГДА игрок добавляет приложение на домашний экран, ТО Система ДОЛЖНА запускаться в полноэкранном режиме
6. Система ДОЛЖНА использовать архитектуру, позволяющую легко обернуть приложение в Capacitor или React Native для публикации в App Store и Google Play
7. Система ДОЛЖНА кэшировать критические ресурсы для быстрой загрузки
8. Система ДОЛЖНА работать в офлайн-режиме с ограниченной функциональностью

### Требование 14: Игровой баланс

**Пользовательская история:** Как игрок, я хочу, чтобы игра была сбалансированной, чтобы прогрессия была интересной и справедливой.

#### Критерии приемки

1. Система ДОЛЖНА использовать формулу расчета опыта для повышения уровня, где каждый следующий уровень требует больше опыта
2. КОГДА персонаж выполняет активность, ТО Система ДОЛЖНА начислять опыт пропорционально сложности активности
3. Система ДОЛЖНА начислять сомы пропорционально риску и сложности активности
4. ЕСЛИ активность имеет негативные последствия, ТО Система ДОЛЖНА применить их с определенной вероятностью
5. Система ДОЛЖНА обеспечивать, чтобы начальные активности были доступны персонажам первого уровня

**Пользовательская история:** Как игрок, я хочу видеть красивые анимации и немедленную реакцию на свои действия, чтобы игра была динамичной и увлекательной.

#### Критерии приемки

1. КОГДА игрок нажимает на кнопку активности, ТО Система ДОЛЖНА отобразить визуальную реакцию в течение 100 миллисекунд
2. КОГДА изменяется состояние персонажа, ТО Система ДОЛЖНА обновить отображение в интерфейсе с плавной анимацией
3. Система ДОЛЖНА использовать CSS анимации или JavaScript анимации для переходов между состояниями
4. КОГДА выполняется активность, ТО Система ДОЛЖНА отображать анимированный индикатор прогресса
5. Система ДОЛЖНА использовать анимации появления для новых элементов интерфейса
6. КОГДА персонаж получает опыт или сомы, ТО Система ДОЛЖНА отобразить анимацию начисления
7. Система ДОЛЖНА использовать микроанимации для улучшения пользовательского опыта
8. Все анимации ДОЛЖНЫ быть оптимизированы для производительности на мобильных устройствах
9. Система ДОЛЖНА предоставлять звуковую обратную связь для ключевых игровых событий (опционально)

### Требование 16: Донатная валюта и косметические предметы

**Пользовательская история:** Как игрок, я хочу покупать за донаты косметические улучшения, чтобы персонализировать своего персонажа без влияния на игровой баланс.

**ХОРОШО (профессиональный стиль):**
```typescript
/**
 * Calculates combat damage with defense mitigation
 * 
 * Defense reduces damage up to 75% max to prevent invulnerability.
 * Formula: damage = attack * (1 - min(0.75, defense/100))
 * 
 * @param {CombatStats} attacker - Attacking entity stats
 * @param {CombatStats} defender - Defending entity stats
 * @returns {number} Final damage after mitigation
 */
function calculateDamage(attacker: CombatStats, defender: CombatStats): number {
  const defenseReduction = Math.min(0.75, defender.defense / 100);
  return attacker.attack * (1 - defenseReduction);
}
```
